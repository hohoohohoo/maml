[C1] Current-Path Representation and Sequential-Cell Modeling (R-A Q1, R-C W1; extraction for R-D Q1)

This is the central concern shared across reviews, so we consolidate it here. We first describe the current-path/sequential-cell representation — (i) what it is, (ii) how it handles sequential cells, (iii) how it is extracted — then answer R-A's borrow-vs-predict question and report all-corner coverage.

(i) Turn-on-path abstraction (Sec. 3.3). Each timing arc is represented as its arc-specific turn-on subgraph — the conductive paths from the supply rail to the switching net (PMOS-from-VDD for rise, NMOS-from-VSS for fall). Cell identity is never an input, which is what lets a single meta-initialization transfer to topologies absent from training.

(ii) Sequential cells — internal feedback loops via loop-closing. A naïve forward path cannot represent state-retaining cells: the cross-coupled feedback loop in a C2MOS flip-flop's keeper inverter does not lie on the forward conduction path, yet it shapes the CLK→Q waveform through contention current and gate-capacitive loading at the shared storage net. Our extraction adds a loop-closing pass that walks the feedback edge and appends one PMOS pull-up + one NMOS pull-down closing-stage (rails → storage net) per cross-coupled storage net, so both keeper devices — and the contention-current path between them — appear as conductive edges in the same per-arc graph as the forward driver, not merely as a hidden capacitive load. A visited-node filter bounds recursion through the feedback edge, so there is no dimensional explosion (directly answering R-C): the subgraph stays restricted to the actively-conducting devices of the arc, which for a flip-flop is far smaller than the full netlist. Empirical verification on the strictly held-out C2MOS sequential cells confirms this: the turn-on graph consistently beats the full transistor netlist across both cell-delay and transition targets and both interpolation and extrapolation regimes — PDF [Figure C1-a].

(iii) Extraction algorithm (R-D Q1). The graph is extracted automatically per arc by a stage-wise backward traversal: polarity-restricted DFS for the conductive rail→target routes per stage, gate nets of the discovered devices pass to the next stage, and traversal terminates when all gate nets are external inputs; a loop-closing pass handles cross-coupled storage nets. Full pseudocode and per-corner-case handling (parallel / stacked / reconvergent transistors, internal nodes, input-state dependence) are in PDF [Algorithm 1]. Fully automatic from the transistor netlist, no manual annotation.

Constraint LUTs are predicted, not borrowed (R-A Q1). The constraint arcs are predicted through the same framework as the delay LUTs; no DFF metric is borrowed from SPICE. The bisection itself runs only at lib-characterization time and writes a single boundary value to the LUT; our model predicts that boundary by regression, so its forward pass never enters the metastable region and the bisection blowup is absorbed by the training labels, not the graph. The constraint LUT therefore shares the same per-arc graph as the delay LUT — only a normalization alias (output_load → input_slew, since the constraint's second axis is a slew rather than a capacitance) is needed.
