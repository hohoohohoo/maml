[C1] Current-Path Representation and Sequential-Cell Modeling

This is the central concern shared across reviews, so we consolidate it here. We first describe the current-path/sequential-cell representation — (i) what it is, (ii) how it handles sequential cells, (iii) how it is extracted — then answer R-A's borrow-vs-predict question and report all-corner coverage.

(i) Turn-on-path abstraction (Sec. 3.3). Each timing arc is represented as its arc-specific turn-on subgraph — the conductive paths from the supply rail to the switching net (PMOS-from-VDD for rise, NMOS-from-VSS for fall). Cell identity is never an input, which is what lets a single meta-initialization transfer to topologies absent from training.

(ii) Sequential cells — internal feedback loops via loop-closing. A naïve forward path cannot represent state-retaining cells: the cross-coupled feedback loop in a C2MOS flip-flop's keeper inverter does not lie on the forward conduction path, yet it shapes the CLK→Q waveform through contention current and gate-capacitive loading at the shared storage net. Our extraction adds a loop-closing pass that walks the feedback edge and appends one PMOS pull-up + one NMOS pull-down closing-stage (rails → storage net) per cross-coupled storage net, so both keeper devices — and the contention-current path between them — appear as conductive edges in the same per-arc graph as the forward driver, not merely as a hidden capacitive load. A visited-node filter bounds recursion through the feedback edge, so there is no dimensional explosion (directly answering R-C): the subgraph stays restricted to the actively-conducting devices of the arc, which for a flip-flop is far smaller than the full netlist. Empirical verification on the strictly held-out C2MOS sequential cells confirms this: the turn-on graph consistently beats the full transistor netlist across both cell-delay and transition targets and both interpolation and extrapolation regimes — PDF [Figure C1-a].

(iii) Extraction algorithm. The graph is extracted automatically per arc by a stage-wise backward traversal: polarity-restricted DFS for the conductive rail→target routes per stage, gate nets of the discovered devices pass to the next stage, and traversal terminates when all gate nets are external inputs; a loop-closing pass handles cross-coupled storage nets. Full pseudocode and per-corner-case handling (parallel / stacked / reconvergent transistors, internal nodes, input-state dependence) are in PDF [Algorithm 1]. Fully automatic from the transistor netlist, no manual annotation.

Constraint LUTs are predicted, not borrowed. The constraint arcs are predicted through the same framework as the delay LUTs; no DFF metric is borrowed from SPICE. The bisection itself runs only at lib-characterization time and writes a single boundary value to the LUT; our model predicts that boundary by regression, so its forward pass never enters the metastable region and the bisection blowup is absorbed by the training labels, not the graph. The constraint LUT therefore shares the same per-arc graph as the delay LUT — only a normalization alias (output_load → input_slew, since the constraint's second axis is a slew rather than a capacitance) is needed. Per-constraint-type accuracy across all six constraint formats (setup / hold / recovery / removal / non_seq_setup / non_seq_hold), aggregated over the held-out sequential cells, is in PDF [Table C1-b].


[C2] On Technical Novelty

We respectfully clarify that our contribution is not "apply MAML to timing characterization." MAML is the foundation; the technical content is a domain-specific reformulation built on top of it so that few-shot adaptation works across unseen cell topologies. We develop three axes on top of this foundation: the cell-identity-free current-path representation (detailed in [C1]), the decoupled device-physics features (N-a), and the dual-stage selective adaptation (N-b).

(N-a) Decoupled device-physics features as the meta-learning signal (Sec. 3.1). What transfers across topologies is device physics, not gate behavior — hence T_ox, DIBL, SCE as independent node features rather than a single lumped V_th. The same rationale governs the current-path representation in [C1]: both axes deliberately avoid cell-identity-bound quantities. Going from MLP_MAML to GCN_MAML under the same MAML procedure and adaptation, varying only the feature/graph granularity, isolates this effect — the additional gain is attributable to the representation, not to the mere presence of MAML.

(N-b) Dual-stage selective adaptation (Sec. 3.4). Adaptation is two-stage rather than vanilla MAML inner-loop SGD: a closed-form Δ-scale + offset alignment first, then Adam-based refinement only when the residual warrants it. Paper Table 6 quantifies this split — alignment alone already recovers most per-task accuracy (evidence that MAML pretraining produced a topology-transferable initialization), and the selective-Adam second stage closes the residual gap while remaining faster than Full Adam by skipping refinement on tasks already aligned.


[R-A] Response to Reviewer A

We address R-A's two questions here: Q1 → [C1] (the common block on current-path representation and sequential-cell modeling, which directly answers R-A's borrow-vs-predict and metastability-bisection sub-questions); Q2 is handled below.

Q2 — Pessimism control during few-shot adaptation. TAMEL supports an adaptation-time pessimism knob without retraining the meta-initialization. In our implementation, the inner-loop MSE is replaced by a pinball / quantile loss with τ > 0.5, so under-prediction errors are penalized more strongly than over-prediction errors during few-shot adaptation. We further compose this with a safe-margin ε added to the support targets during grad/move normalization, which shifts the adapted delay curve upward by ε·y_std·grad in raw delay units. The two knobs are orthogonal — τ controls the asymmetric residual penalty, while ε controls an explicit upward target shift — so we report the joint (τ, ε) Pareto trade-off between accuracy and pessimism. This does not constitute a formal sign-off bound by itself, but provides a calibrated pre-signoff mode that substantially reduces under-prediction while preserving low NRMSE.

Empirically, combining a moderately skewed pinball quantile loss with a small safe-margin shift gives the best Pareto point under a strict accuracy budget: NRMSE_geo remains below ~0.9% (vs. ~0.65% for the released TAMEL), while the prediction is tilted toward over-estimation — the under-prediction rate drops from a near-symmetric ~50% to roughly 10% on average, and the observed worst-case under-prediction remains a small fraction of the per-task delay range. 

[R-B] Response to Reviewer B

We address R-B's six weaknesses and two questions here, with W3 / Q1 covered in [C2] and the remainder handled in place.

W1 — Input parameters across the compared models are consistent (Sec. 3.3, paper Tables 1–2). All compared models share the same three input feature categories — process (T_ox, DIBL, SCE), operating (V, T, slew, C_load), and cell-structural (current-path derived) — with only the granularity of the cell-structural feature differing between MLP and GCN. Both structural representations are explicitly current-path-derived, encoding the same inductive bias at different granularity, not a different parameter set. Going from MLP_MAML to GCN_MAML holds the seven process/operating features fixed and varies only this structural granularity — confirming the gain comes from the shared bias at finer granularity, not from an input mismatch.

W4 / W6 — Dataset scale and runtime are commensurate, not excessive. Each training cell carries on average ~33 K (Commercial) / ~163 K (ASAP7) independent V-to-delay tasks at 61 V_dd sweep points, yielding ~847 M training samples and ~148.7 M strictly held-out test samples across both PDKs, with explicit hold-out by both cell topology and drive-strength variant. The runtime the reviewer flags is over this corpus, not a small dataset — TAMEL pretraining is ~8 h per PDK plus ~2–6 h per online adaptation, 2–3 orders of magnitude shorter than the exhaustive SPICE re-characterization the library would otherwise require (~1,040 h Commercial / ~3,376 h ASAP7), an effective ~530× / ~550× speedup.

W5 — Results are not limited to TT. The TT-only scope applies only to paper Table 5 (path-level STA validation); per-LUT NRMSE in paper Table 4 already spans the five process corners per §4.1. We extended the same flow / circuits / ΔPath Delay / ΔWNS / ΔTNS metrics to all five process corners (FF, FS, TT, SF, SS) across 0–100 °C — per-circuit aggregate in PDF [Table B-W5].

Q1 — Why MLP+MAML ≈ GCN+MAML. The two converge in test accuracy, but MAML's contribution is not uniform across backbones: its improvement factor over no-MAML is consistently 1.2–2× larger on the GCN, and a same-architecture reversal — without MAML the GCN can underperform the MLP, with MAML the GCN leads every category — rules out a backbone-agnostic reading. Mechanistically, the GCN's per-arc current-path graph carries finer-grained device-level information than the MLP's scalar abstraction; that extra detail gives the GCN more transferable capacity in principle but makes naive cross-topology generalization harder — without a meta-learning signal the fine-grained representation overfits per task, which is why the no-MAML GCN trails even the MLP. With MAML, the meta-learned initialization gives both backbones a transferable starting point, and the inner-loop online adaptation closes the per-task residual — which together drive the average convergence — while the bi-level objective keeps the GCN's finer-grained graph detail transferable rather than per-task overfit. The net effect is a small but consistent NRMSE refinement, most visible on multi-stage compositions where this detail is non-redundant.

W2 / Q2 — Metrics. We add a category-averaged MAE (ps) table in paper Table 4's layout — PDF [Table B-W2] — so the entries are directly interpretable in ps rather than the unit-free NRMSE. Path-level ΔPath Delay / ΔWNS / ΔTNS extension across all five corners is in PDF [Table B-W5] (paper Table 5's ΔPath Delay / ΔWNS already provides the TT-corner reference).
